# 分阶段开发计划

本项目采用小步推进。每一步只完成一个稳定目标，完成后再进入下一步。

## 第 0 步：建立项目规范

目标：

1. 创建 `docs/` 文档。
2. 创建 `dev-daily/` 每日开发记录。
3. 在 `CLAUDE.md` 中写入协作和记录规则。

完成标准：

1. 文档路径清晰。
2. 每日记录格式固定。
3. 后续开发前能快速确认下一步做什么。

## 第 1 步：整理最小目录结构

目标：

1. 基于现有 Expo 项目整理源码目录。
2. 保留必要页面。
3. 明确聊天页和设置页的位置。

建议改动：

1. 保留 `src/app/_layout.tsx`。
2. 保留或改造 `src/app/index.tsx` 为聊天页。
3. 新增 `src/app/settings.tsx` 作为配置页。
4. 新增业务目录：`services/`、`storage/`、`types/`、`utils/`。

完成标准：

1. Expo 可以正常启动。
2. 页面路由不报错。
3. 文件职责和目录结构一致。

## 第 2 步：完成静态界面

目标：

1. 做出聊天页静态界面。
2. 做出 API 配置页静态界面。
3. 暂时不接真实请求。

完成标准：

1. 用户能看到输入框、发送按钮、消息展示区域。
2. 用户能进入设置页。
3. 设置页能展示表单。

## 第 3 步：实现本地 API 配置保存

目标：

1. 保存后端 API 地址。
2. 重新打开 App 后能读取配置。
3. 配置缺失时聊天页能提醒用户。

完成标准：

1. 保存配置后返回聊天页可用。
2. 清空或缺失配置时有明确提示。
3. 不记录真实密钥到日志或源码。

## 第 4 步：封装后端请求

目标：

1. 在 `services/` 中封装请求后端的方法。
2. 只处理最简单的提问和回答。
3. 加入基础错误处理。

完成标准：

1. 输入问题后可以发送到后端。
2. 后端返回内容可以显示。
3. 网络失败时 App 不崩溃。

## 第 5 步：完善聊天流程

目标：

1. 管理用户消息和 AI 回复。
2. 增加加载中状态。
3. 增加失败提示和重试入口。

完成标准：

1. 用户发送问题后立即看到自己的消息。
2. 请求中有明确状态。
3. 成功和失败都有清楚反馈。

## 第 6 步：基础验收和清理

目标：

1. 检查类型、lint 和启动。
2. 删除无用模板内容。
3. 补充 README 或使用说明。

完成标准：

1. 项目能稳定启动。
2. 核心流程可以手动跑通。
3. 文档和每日日志已更新。
