# 执行标准

## 每次开发前

1. 先阅读 `docs/DEVELOPMENT_PLAN.md`，确认当前只做哪一步。
2. 检查 `dev-daily/` 当天日志是否存在；不存在就创建。
3. 确认本次改动不超出当前步骤。

## 每次开发中

1. 不一次性生成大量无关代码。
2. 优先修改少量文件并保持可运行。
3. 遇到不确定的技术点，先查当前 Expo 版本文档。
4. 不删除用户已有改动，除非用户明确要求。
5. 不把真实密钥写进源码、文档或日志。

## 每次开发后

1. 记录完成事项到当天日志。
2. 记录遗留待办到当天日志。
3. 记录执行过的验证命令和结果。
4. 如有失败验证，说明原因和下一步。

## 每日开发日志格式

每日日志放在：

```text
dev-daily/YYYY-MM-DD.md
```

每份日志包含：

1. 今日目标。
2. 已完成。
3. 待办事项。
4. 验证记录。
5. 风险与备注。

## 推进节奏

推荐节奏：

1. 一次只做一个小目标。
2. 每个目标完成后先验证。
3. 验证通过后再进入下一步。
4. 如果新手理解成本变高，优先补解释文档，而不是继续加功能。
