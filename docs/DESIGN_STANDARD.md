# 设计规范

## 设计目标

App 面向学习场景，界面应清晰、安静、容易理解。优先保证输入、阅读和错误反馈体验，不追求复杂视觉效果。

## 页面原则

1. 首页就是聊天页，不做营销式欢迎页。
2. 设置页只放当前跑通需要的配置项。
3. 页面层级尽量少，用户能快速回到聊天页。
4. 按钮文案要明确，比如“发送”“保存配置”“重新发送”。

## 聊天页状态

聊天页至少考虑：

1. 初始状态：提示用户输入学习问题。
2. 未配置状态：提示先完成 API 配置。
3. 输入状态：用户可以编辑问题。
4. 加载状态：发送后显示正在请求。
5. 成功状态：显示 AI 回复。
6. 失败状态：显示错误原因和重试入口。

## 设置页状态

设置页至少考虑：

1. 未填写：展示空表单。
2. 已填写：展示已保存配置。
3. 保存成功：明确提示保存完成。
4. 保存失败：展示错误提示。

## 视觉规范

1. 保持简洁，不使用过多颜色。
2. 文本字号保证可读。
3. 输入框、按钮、消息气泡要有足够点击和阅读空间。
4. 错误提示使用醒目但不过度刺眼的样式。
5. 不让文字溢出按钮或卡片。

## 文案规范

1. 面向新手用户，少用技术黑话。
2. 错误提示要说明用户下一步可以做什么。
3. 不显示原始技术错误堆栈。
4. API Key、Token 等敏感内容默认不明文展示完整值。

## 可访问性

1. 重要按钮要有清晰文字或可识别图标。
2. 点击区域不能太小。
3. 加载、错误、空状态都要能通过文字理解。
